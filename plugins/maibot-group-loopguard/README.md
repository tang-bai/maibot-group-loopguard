# 群聊复读守卫（Group Loop Guard）

同群放了不止一个 AI 机器人时，机器人之间会互相"接话"：A 回一句、B 回一句，
几轮之后两边开始说高度相似甚至逐字重复的内容。本插件把这条链路掐掉。

## 身份判定（v1.3）

- 自身账号用于丢弃回声；真人白名单优先于机器人名单与学习名单。
- 未知账号默认放行，不把“身份未知”等同真人。@机器人、昵称命中、单次复制都不直接定性；昵称强匹配须显式开启 trust_name_patterns。
- 默认180秒内至少3轮回声、至少2种来源文本，且至少2轮确实复述了紧邻的已知bot内容，才临时学习。纯未知账号互相复述需至少4轮、3种来源文本。
- 每轮来源与候选正文均至少12字，长度比≥0.65，来源距候选≤60秒；可通过 identity.behavior_* 配置。引用组件不属于本人正文。
- 证据足够的本条仍放行，下一条起应用bot规则；提升时消耗证据，过期后重新观察。自动学习只在当前平台、当前聊天流有效，默认30分钟过期。
- /loopguard who 显示身份依据与证据；误判可用 forget 清学习与证据，并将真人加入 human_accounts。

## 频率嫌疑（可选，默认关闭）

默认60秒内≥5条、≥70%紧接别人发言（12秒内），仅提示嫌疑；还需≥70%是响应已知bot，且至少2条bot响应，才累计一个独立窗口。每账号累计3个窗口才临时标记30分钟，同一窗口不重复计数，10分钟过期。

接话只看紧邻上一条消息，因此“别人一句后自己连发”仅首句算响应。普通真人之间快速对话不累计bot标记窗口。对于不复制文本的未知bot，可先启用 dry_run，再启用 suspect.enabled；慢模型可调大 responsive_within_seconds 和 window_seconds。

这些行为信号没有真实身份保证；活跃真人长期对话bot也可能命中，建议配置真人白名单。群流量大时应调大 detect.max_records，容量上限优先于时间窗口。

## 协作机器人互认（v1.3，可选）

同一个部署的多账号可通过 `identity.peer_bot_config_key` 从宿主配置读取平台:账号列表，热重载时刷新。仅信任实际由适配器提供的扩展字段时才开启 `trust_protocol_bot_flag`；标准OneBot v11没有通用 `sender.bot`。

跨框架受控bot可配置相同的 `cooperative_secret`，且各自开启 `sign_outgoing`：发送前在正文尾部附加可见的 `[LG1:时间戳:HMAC]`，入站校验时绑定平台、聊天流、真实发送账号和正文；校验成功直接判作bot。未配密钥、文本（含标点）篡改、跨账号转发、超时5分钟或普通可见标签都不会通过。不要把密钥发到群里。签名依赖宿主实际发送 `modified_kwargs.message` 且保持文本组件；先在真实适配器检查两台bot的出站文本和入站原始组件。

由于可见标记会展示在QQ群中，默认关闭外发签名。已知bot ID仍优先用 `bot_accounts`，真人白名单优先于签名/适配器字段。

## 它会做什么

| 位置 | Hook | 行为 |
| --- | --- | --- |
| 入站 | `chat.receive.before_process` | 识别机器人身份 + 复读判定，命中即 `abort`，消息不进主链、不入库、不触发推理 |
| 出站 | `send_service.before_send` | 查重与每流独立的出站熔断；可选发送附带协作签名 |
| 规划 | `maisaka.planner.before_request` | 可选：冷却期内摘掉 `reply` 工具，省掉一整轮推理 |
| 频率 | `frequency.set_adjust` | 可选：冷却期内把该聊天流的回复频率倍率压到 0 |

## 它凭什么判断"这是复读"

1. **身份层**：自身账号 → 真人白名单 → 机器人名单 → 有作用域的多轮行为学习；昵称默认仅作弱提示。
2. **内容层**：文本规范化（去 @ / CQ 码 / URL / 标点 / 表情）后做
   exact digest、SimHash（只认逐字重复）、2-gram Jaccard 与 2-gram 包含度。
3. **节奏层**：连续机器人消息条数、两个账号交替接话、短时间内消息爆发。
4. **退避层**：已识别bot命中后按指数退避冷却（默认 120s × 2ⁿ，上限 1800s）。
5. **无身份兜底**：默认单流60秒最多6条出站，第7条静默120秒；未知账号发言不会清零，明确真人白名单可清零。

## 安装

把整个 `maibot-group-loopguard/` 目录放进 MaiBot 的 `plugins/` 下，重载插件即可。
首次加载会在插件目录生成 `config.toml`，也可以直接在 WebUI 插件配置页改。配置页字段均为中文显示名，`config.toml` 的键名保持英文。

依赖：MaiBot `1.3.x` + `maibot-plugin-sdk >= 2.0.0`（Host 自带 Runner 会拉起依赖）。

## 最小可用配置

```toml
[plugin]
enabled = true
dry_run = false

[identity]
# 同群其它机器人的 QQ 号，强烈建议显式登记
bot_accounts = ["123456789", "987654321"]
human_accounts = ["确认的真人账号"]
trust_name_patterns = false
learned_ttl_seconds = 1800
```

其余阈值保持默认即可；调参说明见仓库内 `docs/02-使用与部署.md`。

## 命令

| 命令 | 说明 |
| --- | --- |
| `/loopguard` | 查看当前聊天流的链条长度、退避档位、剩余冷却、拦截计数 |
| `/loopguard who [平台:stream_id]` | 列出当前身份、判定来源、回声与频率证据；未知显示待观察 |
| `/loopguard reset [stream_id]` | 重置指定流（留空重置全部） |
| `/loopguard learn <账号>` | 手动把某个账号记为机器人 |
| `/loopguard forget <账号>` | 移除行为学习记录 |
| `/loopguard on` / `off` | 本进程内临时开关 |

控制台、WebUI 始终有权限；QQ 群里需要在 `[command] command_operators` 里登记 QQ 号。

## 测试

核心算法不依赖 `maibot_sdk`，可以单独跑：

```bash
cd plugins/maibot-group-loopguard
python -m unittest discover -s tests -v
```

## 已知边界

- 语义级改写不由指纹证明；链条与交替节奏只对已识别bot生效。不复读的未知账号可开启可选频率嫌疑或人工登记。
- 只约束本实例，另一台机器人需要各自装上插件（或用 `[arbiter]` 让发言权错开）。
- 拦截后的消息不会进入记忆，这是有意为之：复读内容进上下文只会让下一轮更像复读。

## 升级

v1旧学习名单与冷却自动清理（含手工临时learn），统计与配置中的bot_accounts保留。v2保存平台、流、过期时间与来源，离线时长从冷却扣除；因指纹不持久化，重启不恢复无依据的消息链条。已有配置值会保留，建议检查 learned_ttl_seconds 是否仍为旧默认86400。

发送前检查（包括熔断计数）会在平台确认成功前记账；若适配器发送失败，同文重试可能被查重，需要重置流后再试。
