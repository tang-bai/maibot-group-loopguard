# CHANGELOG

## 1.3.0

- 新增独立出站频率熔断：默认单聊天流60秒内最多放行6条，第7条静默120秒；不依赖发送者bot身份，未知账号发言不清预算，仅真人白名单重置。不同流隔离，计数与剩余冷却跨重载/重启保留。
- 新增共享机器人名册配置键、仲裁名单复用以及可选可信适配器bot扩展字段；OneBot v11标准没有通用的sender.bot，默认不信任该扩展。
- 增加可选受控bot间的LG1协作标记：对平台、流、发送者、时间和正文做HMAC签名，验证后直接识别；文本标记、转发、篡改、跨群与超时均不会单凭标记定性。默认不在外发消息追加可见标记，需在适配器现场验证。
- 为上述行为新增单元及Hook回归，合计98项，当前无真实SDK环境下95通过、3项Schema测试跳过。发送前计数仍按尝试记账；跨框架签名投递待真实适配器验证。
- 调研参考：[openclaw-napcat](https://github.com/Daiyimo/openclaw-napcat)、[Pallas-Bot](https://github.com/PallasBot/Pallas-Bot/blob/main/pallas/core/platform/multi_bot/bot_filter.py)、[AstrBot多Bot循环问题](https://github.com/AstrBotDevs/AstrBot/issues/10724)。

## 1.2.0

- 身份判定改为保守证据机制：单次复制、@机器人、昵称命中默认均不直接定性。新增真人白名单，优先于机器人名单和自动学习（自身回声识别除外）。
- 行为学习累计多轮回声、不同来源文本及已知bot锚点；全未知场景额外增加轮数要求。回声响应间隔独立可配，默认60秒以覆盖较慢模型；学习结果默认保留30分钟。
- 修复频率统计跳过连续自身消息的问题；嫌疑计数、窗口节流均按账号独立。频率标记还要求响应已知bot的比例达标，普通真人快速对话只提示嫌疑。
- 学习、行为证据、频率窗口和冷却均按平台和聊天流隔离；提升身份时消耗证据，过期后须重新观察，旧证据不再无限续期。引用内容不计入本人正文，@组件不再吞掉紧邻中文文本。缺失session时使用稳定的群/私聊键；缺失发送者不清冷却。
- /loopguard who 显示当前身份、依据、回声与已知bot响应证据，不再把未知身份断言为真人；forget同时清除累计证据。
- 修复过期链条、旧出站指纹、非交替双账号误判，以及演习模式仍修改规划器工具的问题。
- 状态格式升级至v2：清理旧版无作用域学习/冷却（统计保留）；新格式重启后按实际离线时长扣减冷却；指纹不持久化，因此不恢复无依据的消息链条。
- 新增误判/漏判边界测试；完整84项，当前无真实SDK环境下81项通过、3项Schema测试跳过。未进行真实群聊准确率评测。

## 1.1.0

- 新增「频率嫌疑」识别：按「高频 + 紧跟别人发言」识别未登记的 bot，弥补昵称/名单/行为学习都抓不到的场景。判定分两步：窗口内发言次数达标 **且响应式发言占比达标**，再累计 N 次高频窗口才标记。默认关闭，建议先开演习观察。
- 修复 `check_frequency` 的变量名冲突：循环变量 `record` 覆盖了函数参数 `record: bool`，导致 `record=False` 的只读查询仍会写入嫌疑计数。
- 修复 `_last_suspect_ts` 初始值：从 `0.0` 改为 `-inf`，避免首次评估被"距离上次不足一个窗口"挡住。
- 测试 44 个：26 算法 + 15 Hook 冒烟 + 3 Schema 标签。

## 1.0.2

- 新增 `/loopguard who`：列出窗口内每个发送者被判成机器人还是人类、各自的消息条数与最后活跃时间，并给出可一键复制的 `learn` 命令。互聊拦不住时先跑这条，九成是对方账号没被识别。
- 结构性兜底：消息只 @ 已知机器人（含自身账号）时，发送者本身按机器人处理，不再依赖昵称或名单。
- 文档补充「装完还在互聊」的三步排查路径：先 `who`，再 `learn`，再看 `dry_run` / `enabled` / `platform_scope`。
- 测试 37 个：22 算法 + 12 Hook 冒烟 + 3 Schema 标签。

## 1.0.0

首个版本。

- 入站拦截：`chat.receive.before_process` 上做身份识别 + 复读判定，命中即中止消息链。
- 出站兜底：`send_service.before_send` 对回复正文再查一次重，冷却期内直接取消发送。
- 身份识别：显式账号名单、行为学习（复述其它机器人内容即自动登记）、昵称正则三层。
- 复读检测：文本规范化 + SimHash（逐字重复）+ 2-gram Jaccard + 2-gram 包含度。
- 节奏检测：连续机器人消息链条、双账号交替接话、短时爆发。
- 指数退避冷却：默认 120s 起、×2 递增、1800s 封顶，人类发言立即清零。
- 可选软手段：`frequency.set_adjust` 压低回复频率、规划器摘除 `reply` 工具。
- 多实例仲裁：按账号字典序决定谁先开口，另一方提前退让。
- 状态持久化：行为学习名单与冷却状态写入 `data/plugins/<plugin_id>/loopguard_state.json`。
- 命令：`/loopguard status|reset|learn|forget|on|off`。
- 演习模式（`dry_run`）：只记日志、照常放行，用于上线前观察误杀。
