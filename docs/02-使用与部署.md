# 群聊复读守卫 · 使用与部署

> 插件版本 1.0.0 · 适配 MaiBot 1.3.x · 插件 SDK ≥ 2.0.0
> 方案背景与算法细节见 [01-方案设计.md](./01-方案设计.md)

---

## 1. 前置条件

| 项 | 要求 | 检查方式 |
| --- | --- | --- |
| MaiBot | 1.3.0 ~ 1.3.99 | 启动日志里的版本号，或 WebUI 底部版本 |
| 插件 SDK | ≥ 2.0.0（Host 侧 Runner 自带，插件本身无需 pip 安装） | WebUI → 插件 → 运行时信息 |
| 平台 | 默认只对 `qq` 生效，可在 `identity.platform_scope` 扩展 | 见 §3.2 |

## 2. 安装

### 2.1 手工放置（最直接）

1. 把 `maibot-group-loopguard/` 整个目录放进 MaiBot 目录下的 `plugins/`：

```
MaiBot/
└── plugins/
    └── maibot-group-loopguard/
        ├── _manifest.json
        ├── plugin.py
        ├── loopguard_core.py
        ├── README.md
        └── CHANGELOG.md
```

2. 启动或重载。任一方式：
   - 重启 `python bot.py`；
   - WebUI → 插件 → 找到「群聊复读守卫」→ 重载；
   - 命令 `/pm reload maibot-community.group-loop-guard`。
3. 首次加载成功后，插件目录会出现 `config.toml`（Runner 依 `config_model` 生成），WebUI 的插件配置页也会出现对应表单。

### 2.2 从 zip 安装

```bash
# 在 MaiBot 根目录执行
unzip maibot-group-loopguard-1.0.0.zip -d plugins/
```

> 压缩包内的条目名必须是 `/` 分隔。Windows 自带的 `Compress-Archive` 写的是反斜杠，WebUI 安装器会直接判为非法路径；
> 自己打包请用 `python tools/build_package.py`，它按安装器规则生成并自检。

然后在 WebUI 插件页点「重载」。

### 2.3 验证加载成功

- Runner 日志出现：`复读守卫已加载：enabled=True dry_run=False self=['你的Bot账号']`；
- WebUI 插件列表里状态为「已启用」；
- 群里发 `/loopguard`，返回一条包含「连续机器人消息 / 退避档位 / 剩余冷却」的文本（权限见 §5）。

## 3. 配置

> WebUI 配置页显示的是每个字段的中文名（Schema `label`），`config.toml` 里的键名保持英文。若页面仍是英文键名，说明插件没重载或浏览器缓存了旧 Schema：重载插件后硬刷新页面（Ctrl+F5）。

配置文件：`plugins/maibot-group-loopguard/config.toml`，也可以直接在 WebUI 的插件配置页改（保存后热重载，无需重启）。

### 3.1 `[plugin]`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | 总开关 |
| `config_version` | str | `1.0.0` | 配置版本，Runner 用它做迁移判断，**不要手动改** |
| `dry_run` | bool | `false` | 演习模式：判定照跑、日志照打，但一律放行。上线前先开一天 |

### 3.2 `[identity]` 身份识别

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `bot_accounts` | list[str] | `[]` | **最重要的配置**。同群其它机器人的账号，写 `123456789` 或 `qq:123456789` 都行 |
| `self_accounts` | list[str] | `[]` | 本实例自己的账号；留空时自动读 `bot_config.toml` 的 `bot.qq_account` / `bot.platforms` |
| `name_patterns` | list[str] | `["(?i)(bot\|机器人\|助手\|麦麦\|maisaka\|assistant)$"]` | 昵称/群名片正则，命中按机器人处理；写 `[".*"]` 等于关闭这一层 |
| `auto_learn_behavior` | bool | `true` | 未登记账号若在 30 秒内逐字/高包含度复述其它账号的内容，自动临时记为机器人（首条只登记、不额外惩罚） |
| `learned_ttl_seconds` | int | `86400` | 行为学习结果的保留时长（秒） |
| `platform_scope` | list[str] | `["qq"]` | 生效平台；留空 = 全平台。不在名单内的平台一律放行 |

> 标点符号提示：`name_patterns` 是**正则**，在 TOML 里建议用单引号字符串 `'...'` 包住，避免反斜杠转义。

### 3.3 `[detect]` 检测阈值

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `window_seconds` | int | `180` | 滑动窗口长度，窗口外的消息不参与查重 |
| `max_records` | int | `60` | 每流保留的指纹条数 |
| `min_text_length` | int | `4` | 短于该长度的文本不查重（"哈哈""草"不算复读） |
| `simhash_distance` | int | `1` | 逐字重复的快速判定；建议不超过 6，中文短句调大会引入假阳性 |
| `bigram_similarity_threshold` | float | `0.72` | 2-gram Jaccard 阈值，抓近义改写 |
| `bigram_containment_threshold` | float | `0.85` | 2-gram 包含度，抓"抄一遍再补几个字" |
| `max_chain_length` | int | `4` | 连续第几条机器人消息后强制静音（最终保险） |
| `duplicate_chain_threshold` | int | `2` | 连续第几条起，内容重复就拦 |
| `pingpong_span` | int | `6` | 检测交替接话时回看的条数 |
| `pingpong_chain_threshold` | int | `3` | 交替节奏成立的最小连续条数 |
| `burst_count` | int | `6` | 爆发检测条数阈值 |
| `burst_window_seconds` | int | `60` | 爆发检测时间窗 |

### 3.4 `[action]` 处置

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `block_incoming` | bool | `true` | 入站拦截（主刹车）。关掉后消息照常进主链，但判定与冷却仍在记账，出站闸门继续生效 |
| `block_self_echo` | bool | `true` | 拦本实例自己的回声消息 |
| `block_outgoing` | bool | `true` | 发送前再查一次重 |
| `cooldown_base_seconds` | int | `120` | 首次触发的冷却时长 |
| `cooldown_multiplier` | float | `2.0` | 每次再触发的倍率 |
| `cooldown_max_seconds` | int | `1800` | 冷却上限 |
| `human_reset_seconds` | int | `300` | 留档字段（当前实现是人类发言立即清零链条与冷却） |
| `frequency_brake` | bool | `false` | 冷却期内把该流回复频率倍率压到 `frequency_brake_value`（走 `frequency.set_adjust`） |
| `frequency_brake_value` | float | `0.0` | 冷却期倍率，0 = 完全不出声 |
| `frequency_restore_value` | float | `1.0` | 解除冷却时恢复的倍率 |
| `soft_mute_reply_tool` | bool | `false` | 冷却期内从规划器工具定义里摘掉 `reply`，省掉一轮推理 |
| `muted_tool_names` | list[str] | `["reply"]` | 要摘掉的工具名 |
| `notify_on_trip` | bool | `false` | 触发时在当前群发提示；默认关，避免自己刷屏 |
| `notify_text` | str | `（复读守卫已介入，暂停接话）` | 提示文案 |

### 3.5 `[arbiter]` 多实例仲裁

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | 开启账号优先级仲裁 |
| `peers` | list[str] | `[]` | 同群其它实例的账号 |
| `self_priority` | str | `""` | 本实例声明的账号；留空用自动识别的自身账号 |

规则：`peers + 自己` 按账号字符串排序，字典序最小的实例为主实例；非主实例在重复/交替场景提前一步退让。

### 3.6 `[command]` 命令权限

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `command_operators` | list[str] | `[]` | 允许在 QQ 群使用 `/loopguard` 的账号；控制台与 WebUI 始终放行 |

## 4. 配置模板

### 4.1 场景 A：同群两只 MaiBot（推荐起手式）

```toml
[plugin]
enabled = true
dry_run = false

[identity]
bot_accounts = ["另一只的QQ号"]
auto_learn_behavior = true

[action]
soft_mute_reply_tool = true      # 少烧一轮推理
notify_on_trip = false           # 静默处理，别让守卫自己刷屏

[arbiter]
enabled = true
peers = ["另一只的QQ号"]
```

两只机器人都要装，`peers` 里互相填对方账号。

### 4.2 场景 B：群里还有第三方播报机器人（只防死循环，不干扰播报）

```toml
[detect]
duplicate_chain_threshold = 3    # 放宽：播报内容偶尔相似不立刻拦
max_chain_length = 5             # 但要挡住长链条
window_seconds = 240

[identity]
bot_accounts = ["播报号1", "播报号2"]
auto_learn_behavior = false       # 别把正常转发的号学成机器人
name_patterns = ['(?i)^(bot|机器人)$']   # 收紧昵称匹配
```

### 4.3 场景 C：只想省钱，交互手感不变

```toml
[plugin]
enabled = true

[detect]
max_chain_length = 3            # 更早收手
duplicate_chain_threshold = 2

[action]
block_incoming = true
block_outgoing = true
cooldown_base_seconds = 300
cooldown_max_seconds = 3600
frequency_brake = true          # 冷却期彻底不出声
```

## 5. 命令

| 命令 | 说明 | 返回 |
| --- | --- | --- |
| `/loopguard` | 查看当前聊天流状态 | 连续机器人消息数、退避档位、剩余冷却、累计拦截、最近原因、窗口指纹数、全局统计 |
| `/loopguard status <stream_id>` | 查看指定流 | 同上 |
| `/loopguard reset` | 重置全部流状态 | 重置数量 |
| `/loopguard reset <stream_id>` | 重置指定流 | 该流 ID |
| `/loopguard learn <账号>` | 手动把账号登记为机器人（带 TTL） | 确认文本 |
| `/loopguard forget <账号>` | 移除行为学习记录 | 确认文本 |
| `/loopguard on` / `off` | 进程内临时开关（配置文件不变） | 确认文本 |

权限：`is_local_operator`（控制台 / WebUI）直接放行；QQ 群里要求发送者在 `[command] command_operators`。

## 6. 排错

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 插件列表里没有 | 目录层级错（多套了一层同名文件夹） | 确认 `plugins/maibot-group-loopguard/_manifest.json` 存在 |
| 从 ZIP 安装报「ZIP 包含非法路径、链接或加密文件」 | 用 `Compress-Archive` 打的包，条目名是反斜杠 | 改用 `python tools/build_package.py` 重新打包；或解压后直接拷目录进 `plugins/` |
| 加载报「Hook 注册失败」 | Hook 名拼错 / 在不允许 abort 的 Hook 上声明了 `ErrorPolicy.ABORT` | 用本文档对应的 Hook 名；三个 Hook 都声明 `SKIP` |
| 日志有 `dry-run 本应拦截`，但消息照常处理 | 演习模式开着 | 把 `plugin.dry_run` 设为 `false` |
| 该拦没拦 | 对面账号没登记、昵称不像机器人、内容也不重复 | 补 `bot_accounts`，或把 `max_chain_length` 调小 |
| 真人群友被拦 | 昵称正则过宽（例如 `.*`）或行为学习误判 | 收紧 `name_patterns`；`/loopguard forget <账号>`；必要时 `auto_learn_behavior = false` |
| 只有我这边静音，对面还在说 | 对面没装插件 | 两边都装；或先开 `[arbiter]` 让对面承担主发言 |
| 冷却很久不解除 | 群聊一直在互激，每次都在刷新冷却 | 人类发一句话即清零；或 `/loopguard reset` |
| 插件影响启动速度 | 状态文件过大（历史累积） | 删掉 `data/plugins/maibot-community.group-loop-guard/loopguard_state.json` 后重载 |
| 想确认是否生效 | — | 看 Runner 日志关键字 `[loopguard]` |

日志样例：

```
[loopguard] 拦截入站 stream=qq_group_123 sender=10001 reason=duplicate chain=3 cooldown=240s text='那我也来，几点开始'
[loopguard] 取消发送 stream=qq_group_123 reason=cooldown cooldown=180s text='好啊那我们八点见'
[loopguard] 行为识别：小助手(10002) 复述了机器人内容，已临时记为机器人
```

## 7. 验收步骤（真实实例）

1. **静态检查**：`python -m py_compile plugin.py loopguard_core.py`；
2. **算法回归**：

```bash
cd plugins/maibot-group-loopguard
python -m unittest discover -s tests -v      # 期望 34 个用例全部 OK（21 算法 + 10 Hook 冒烟 + 3 Schema 标签）
```

3. **演习**：`dry_run = true`，把两只机器人放进测试群，让它们自然聊 10 分钟，检查日志里 `[dry-run] 本应拦截` 的文本是否都是复读内容；
4. **实战**：`dry_run = false`，重复第 3 步，确认链条在第 2~4 轮收敛，且人类插话后恢复正常；
5. **出站闸门**：在冷却中手动触发一次回复（例如有人 @ 机器人），确认日志出现 `取消发送`；
6. **持久化**：重启 MaiBot，`/loopguard` 仍能看到冷却状态（窗口内指纹不持久化，属预期）。

## 8. 升级、卸载与数据

- **升级**：替换 `plugin.py` / `loopguard_core.py`，重载插件；`config.toml` 会按新 `config_model` 自动补齐新字段，已有值保留。
- **卸载**：WebUI 停用并删除插件，或直接把目录移出 `plugins/`。
- **数据**：`data/plugins/maibot-community.group-loop-guard/loopguard_state.json` 保存学习名单与冷却状态，删掉即彻底重置；不含聊天原文，只有 80 字符截断预览用于排错。

## 9. FAQ

**Q：为什么不直接在 MaiBot 配置里把对方账号屏蔽？**
A：屏蔽词/正则是对**内容**生效的，机器人之间每轮内容都不同，屏蔽词拦不住；本插件判定的是发送者身份 + 节奏结构。

**Q：会不会影响机器人正常接人类的话？**
A：不会。人类消息永远走 `allow` 分支，并顺带清零链条与冷却。

**Q：两只机器人阈值不一样会不会打架？**
A：会不对称，但不会放大问题——阈值紧的那只会先停，松的那只仍受 `chain_limit` 约束。需要确定性时开 `[arbiter]`。

**Q：Focus 模式和普通模式都生效吗？**
A：都生效。入站 Hook 在主链最前面，与聊天模式无关；`soft_mute_reply_tool` 只对 Maisaka 规划器链路有意义。

**Q：被拦下的消息会进记忆吗？**
A：不会。拦截发生在 `SessionMessage.process()` 之前，消息既不入库也不进上下文——这正是本插件省 token 的部分。

**Q：插件自己发的提示会被自己拦吗？**
A：不会。发送时带内部标记，出站闸门直接跳过；`notify_on_trip` 默认也是关的。
